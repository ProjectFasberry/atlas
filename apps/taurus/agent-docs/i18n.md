# Internationalization

Paraglide (inlang), Russian base locale + English. No user-facing string in
JSX, models or toasts.

## Files

| Path | Role |
| --- | --- |
| `messages/ru.json` | Base locale. |
| `messages/en.json` | English. |
| `project.inlang/settings.json` | Locales + message-format plugin. |
| `paraglide/` | Generated; never edit. |
| `shared/locales/helpers.ts` | Exports `translate` (paraglide `m`). |

Add the same nested key to **both** locale files. A missing key is a type error.

## Usage

```ts
import { translate } from "@/shared/locales/helpers";

translate["join.title"]()
translate["gallery.count"]({ count: items.length })
```

- Call the generated function; do not pass a string key.
- Keep keys grouped by page/feature (`join.*`, `support.*`, `modpack.*`).
- Use params (`{count}`, `{date}`) instead of concatenating.
- Do not leave empty message groups (`"shared": {}` breaks the compiler).

## Generation

After editing `messages/*.json`, from `apps/taurus` run:

```bash
pnpm exec paraglide-js compile \
  --project ./project.inlang --outdir ./paraglide \
  --strategy cookie preferredLanguage baseLocale
```

- Dev/build runs the Vite plugin, but `tsc` alone does not regenerate messages;
  compile before `type-check` after adding keys.
- Never edit `paraglide/`; it is generated and gitignored.

## Locale on the server

- `renderer/+server.ts` runs `paraglideMiddleware` and stores the locale in
  Hono context storage.
- `renderer/+onBeforeRoute.server.ts` reads `ctx.var.locale` and writes
  `appState.locale` per request. Do not call `setLocale` globally.
- `renderer/+lang.ts` sets `<html lang>` from `getLocale()`.
- Client language switching uses the cookie strategy; avoid reading
  `navigator.language` in components.

## Dates and numbers

- Use `Intl.DateTimeFormat` / `Intl.NumberFormat` with `appState.locale()`.
- `shared/lib/create-dayjs.ts` is fixed to `ru`; do not use it for English
  dates.
- SSR and client must render the same locale; if a value is client-only, gate
  it with `pageState.isClient`.

## Rules

- No hardcoded Russian/English in components, models or toasts.
- Update both locales in the same change.
- Keep copy short and player-facing; legal/full rules stay in the API content.
- Test both `/` and `/rules` with `ru-RU` and `en-US` browser locales.
