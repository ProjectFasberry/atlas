# UI and styling

Minotaur uses Tailwind CSS v4, `tailwind-variants` (`tv`), `cnfast` and the
`shared/ui` primitives. Do not add a new styling or component library.

## Class rules

- Write Tailwind classes inline; no CSS modules, no styled-components.
- Use `tv({ base, variants, defaultVariants })` for reusable variants and
  `clsx`/`cn` from `cnfast` for conditional classes. Keep the variant object
  next to the component.
- Match the surrounding scale: `rounded-xl`, `gap-2/3/4`, `p-2/3/4`,
  `text-sm/base/lg`, `bg-neutral-800/900`, `text-neutral-400`,
  `border-neutral-800`, `green-500` for actions, `red` for destructive.
- Use `sm:` / `lg:` breakpoints; mobile layout also checks
  `appState.current.isMobile`.
- Inline `style` only for computed values (widths, transforms, dynamic colors).
- No global CSS additions without checking `shared/styles/tailwind.css` and the
  Tailwind theme first.

## Shared primitives

Import from `@/shared/ui/<name>`:

| Primitive | Notes |
| --- | --- |
| `Button` | `background`: `default`, `compound`, `white`, `positive`; `variant`: `default`, `danger`, `minecraft`; `size`: `headless`, `default`, `small`; `isLoading` + `withSpinner`. |
| `Input` | Text input; `variant` default/ghost/danger. |
| `Typography` | `variant` title/subtitle; `color` gray/black/white; `shadow`. |
| `Table` + `TableHeader/Body/Row/Head/Cell` | Standard data tables. |
| `Dialog` helpers | `dialogVariant`, `DialogClose`; use Ark UI `Dialog.Root` with a `Trigger`. |
| `Select` | Ark UI select with `selectVariant`; use it instead of a native `<select>` for user-facing forms. |
| `Switch`, `Checkbox`, `Tabs`, `Tooltip` | Ark UI based. |
| `Skeleton`, `PageLoader` | Loading states. |
| `ErrorBlock` | `title` string; the standard error state. |
| `Avatar`, `Icon` | Icons come from the generated sprite. |
| `SectionWrapper`, `WithHeader` | Private page shell (under `shared/components/app/private/components/ui`). |

Do not restyle a primitive with a parallel implementation; extend its variants
if the change is reusable, otherwise pass `className`.

## Icons

- Use `<Icon name="sprite:<symbol>" />` (e.g. `sprite:loader-2`,
  `sprite:pencil`, `sprite:x`).
- The sprite is generated by `bun run gen:icons` from `public/sprites`; the
  output `shared/types/gen/icon/sprite.gen.ts` is generated and must not be
  edited. `type-check` runs `scripts/fix-sprite.ts` first.
- Other sprite groups are allowed (`common:...`) only if they are generated.

## Dialogs

Use the project's Ark UI pattern; do not hand-roll an overlay and do not drive
open state with a React hook:

```tsx
<Dialog.Root onOpenChange={({ open }) => { if (!open) editor.close(ctx); }}>
  <Dialog.Trigger asChild>
    <Button background="default" onPointerDown={() => editor.open(ctx, item)}>Edit</Button>
  </Dialog.Trigger>
  <Portal>
    <Dialog.Backdrop className={dialogVariant.backdrop()} />
    <Dialog.Positioner>
      <Dialog.Content className={dialogVariant.content("items-start! justify-start!")}>
        <DialogClose />
        <Dialog.Title className={dialogVariant.title()}>Edit</Dialog.Title>
        ...
        <Dialog.CloseTrigger asChild>
          <Button background="positive">Save</Button>
        </Dialog.CloseTrigger>
      </Dialog.Content>
    </Dialog.Positioner>
  </Portal>
</Dialog.Root>
```

- State belongs to the model (`editor.target`, `editor.form`), not `useState`.
- `Dialog.CloseTrigger asChild` closes the dialog; do not toggle a controlled
  `open` from outside without also closing the underlying state.
- The close X is `DialogClose`.

## Tables and lists

- Use the `Table` primitives; key every row by id.
- Show `PageLoader` on first load, `ErrorBlock` on error, and an explicit empty
  state.
- Keep filters, sorting and pagination in the model; the component only renders.
- Do not fetch from a row component; fetch once for the list.

## Forms

- Inputs are controlled by model atoms; `onChange` calls a model action.
- Submit buttons read the mutation's `statusesAtom.isPending` and use
  `isLoading`/`withSpinner` on `Button`.
- Validation errors render next to the field; API errors use a toast/alert.
